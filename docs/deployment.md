# IIS配備手順

## 0. 前提確認

管理者の許可を得た検証用のIISアプリケーションで実施する。サイトの既存アクセス制御、HTTPS、認証設定を引き継ぎ、外部へ公開しない。サーバーへの新規インストールは行わない。ASP.NET 4.xとISAPI拡張等が既に有効であることを確認する。Edge/Chrome等の現行ブラウザーを使用する。

## 1. 配備用ZIPを取得

GitHub Actionsの成功したビルドのArtifacts `InfoBoard-IIS` をダウンロードし、内側の `InfoBoard-IIS.zip` を展開する。ソースコードZIPはそのまま配備できない。ビルド失敗時はログを確認し、配備しない。

## 2. IISアプリケーション作成

1. 専用の配置フォルダ（例: `D:\Web\InfoBoard`）を作成し、ZIPの中身を配置する。`index.html` と `web.config` がフォルダ直下になるようにする。
2. IISマネージャーで専用アプリケーションプール `InfoBoard` を作成。CLR v4.0、統合パイプライン、32ビットアプリケーション有効化=False、プロセス数1、ApplicationPoolIdentityを基本とする。
3. 既存アクセス制限下のサイトにアプリケーションを追加。エイリアス `InfoBoard`、物理パスを配置フォルダ、プールを専用プールに設定する。単なる仮想ディレクトリではなくアプリケーションとして登録する。
4. 既存サイトの認証・IP制限・HTTPS等を継承できているか確認する。親サイト側の設定ロックやハンドラ継承による500.19があれば、他サイトの設定を緩和せず管理者と調整する。
5. 配置フォルダ直下に `App_Data` を新規作成する。配置フォルダへの読み取りと実行、App_Dataへの変更（Modify）を `IIS AppPool\InfoBoard` に付与する。Webルート全体への書き込み権限やEveryoneへの権限追加はしない。IISでApp_Data直アクセスが拒否されることを確認する。
6. 既存のアクセスURLに `/InfoBoard/` を付加してアクセスする。初回API呼び出しでDBが生成される。サーバー全体のIIS再起動は不要。

## 3. 受入チェック（本番利用前に実施）

- 一覧、カード追加・編集・再読込、Markdownの見出し・表・リンク・コード、折りたたみ、色、OSテーマ、スマートフォン幅を確認。
- 2ブラウザーで同一カードの編集を試し、片方だけ取得できる、別カードは編集できる、5秒程度で編集中表示が更新されることを確認。
- 編集中にブラウザー強制終了し、60秒程度後にロックが解放されることを確認（正常離脱なら早期解放）。古いリースからの保存は拒否されることを確認。
- 並べ替えを保存し別画面で同じ順序になること、検索時の並べ替え不可、構造変更との排他を確認。
- 直前状態の復元、再復元、アーカイブ、復帰、CSV全件出力（改行、引用符、日本語、数式を装った文字列を含む）を確認。
- XSSテストとしてMarkdownに `<script>alert(1)</script>` や不正なリンクを入力し、スクリプトが実行されないこと。直接 `/InfoBoard/App_Data/board.db` にアクセスしてもDBを取得できないこと。アクセス制限外から閲覧・API・CSVすべて拒否されること。
- 専用プール再起動後にカードが保持されること。テストカードはアーカイブ、または検証用DBを退避して初期化する。

## 4. 更新とバックアップ

専用プールを停止し、App_Dataの全ファイルをバックアップする（停止中のみコピー）。新規ZIPでアプリファイルを置換するがApp_Dataは保持する。専用プールを起動し、受入確認を実施する。更新失敗時は停止中に以前のアプリとDBバックアップを復元する。DBの保管先とバックアップには適切なアクセス権を設定し、GitHubへ登録しない。CSVだけでは履歴や内部状態を完全復旧できない。

## 5. 障害切り分け

- 500.19: IIS構成・継承・設定ロック。
- 404 (APIのみ): ASP.NET統合モード、アプリケーション登録、拡張子なしURLハンドラー。
- 500 (API): Windowsイベントログ/IISログ、App_Dataの変更権限、SQLite DLLの配置とx64ビット数、ネイティブ依存ランタイムの有無を確認する。必要なネイティブ依存が既存サーバーにない場合は導入制約に照らし方式を再検討し、勝手にインストールしない。
- Markdownライブラリ不足: ソースZIPを配置していないか、配備ZIP内のlibを確認する。

本手順は既存IIS構成による差異があるため、実機の受入確認が必要。
