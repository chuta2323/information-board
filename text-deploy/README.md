# InfoBoard テキスト配備版

従来のv1.2の画面・機能を維持し、ASP.NET標準の動的コンパイル（.ashx）とJSONファイルを使用する。会社で承認済みのソース配置方法で配備すること。ダウンロード制限の解除や迂回は行わない。

## 配備

IIS 10 / .NET Framework 4.7.2以上 / ASP.NET 4.x / 統合モード、ローカルNTFSの専用アプリケーションを使用する。新しいDLLや開発環境は不要。既存のIIS認証・アクセス制御を維持する。

1. 新規の専用配置フォルダを作成し、次の5ファイルをUTF-8（BOM付き可）で保存する。GitHubの各ファイルのRaw内容を承認済みの方法でコピーする。拡張子に.txtが付かないよう確認する。
   - index.html
   - style.css
   - app.js
   - api.ashx
   - web.config
2. 直下に空のApp_Dataを作成する。専用アプリケーションプールのIDにルートの読み取りと実行、App_Dataのみ変更権限を与える。
3. IISで専用プール（CLR v4.0、統合、64ビット、1ワーカー）とアプリケーションを登録する。初回のAPIアクセスでコンパイル・board.json生成が行われる。
4. 実機で以下の受入確認を実施する。既存SQLite版に上書きしないこと。

## 保存・制約

- board.jsonにカード・直前履歴・サイト名・版・操作リースを保持。board.lockのOS排他ロックでプロセス間の更新を直列化する。ファイルを削除してロック解除しない。
- 一時ファイルをフラッシュしてFile.Replaceで置換し、board.previous.jsonに直前ファイルを保持する。直前ファイルは全操作単位でありカードの復元履歴や世代バックアップとは異なる。完全削除したカードがバックアップに残ることがある。
- App_Dataのファイルへの直接HTTPアクセスを禁止する。トークンを含むため外部公開しない。専用プール停止中にApp_Data全体を別の保護された場所へバックアップする。
- 小規模・低頻度利用向け。全ファイルを読み書きするため、JSONは1600万文字、ファイルは6400万バイトを上限とする。容量・負荷を実機確認する。共有ネットワークドライブは対象外。
- 旧board.dbは自動移行しない。既存データは旧版の専用ディレクトリに保持する。移行が必要なら別途承認済みの移行作業を行う。同じApp_Dataに旧DBがある場合は空のJSONを自動生成しない。
- 更新は専用プール停止、App_Dataバックアップ、5ファイル置換、プール開始、Ctrl+F5。元のデータを削除しない。

## 受入確認

- 初回APIが成功し、board.jsonが生成される。App_Data/board.json、board.previous.json、board.lockへのHTTPアクセスは拒否される。
- カード作成・改行・編集・直前状態復元・前後への並べ替え・検索・アーカイブ・復帰・完全削除・CSV・サイト名変更。
- 別ブラウザーで排他・別カード同時編集・5秒同期・60秒リース失効・競合拒否。
- 専用プール再起動後もカードとサイト名が保持される。障害時はプール停止中にバックアップから復旧する。
- Windows上のC#コンパイル・ストア回帰テストと実際のIIS受入確認は別物。両方を確認してから業務利用する。
